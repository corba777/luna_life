Collective Falsification

Every agent in a population starts with the same wrong rule. Each can run a few experiments and tell its neighbours what it found. Does the population find its error?

The question was raised by Michal Valko (Isara Labs and Inria).

Current answer, from two models: it depends on the model, and the failure has two separate causes.

  • gpt-oss-20b mostly stays wrong. When the error is rare (δ = 1/64), its tests never hit it. When it is common (δ = 1/8), agents find counterexamples and switch their own rule, but almost never pass the evidence on: 84 finders, 6 shared counterexamples, 10–26 % of the population on the true rule at the end.
  • Luna corrects the error. It picks tests that separate the candidate rules and shares what it finds. In three of four cells the whole population ends on the true rule, including the rare-error cell with four tests per agent. With one test per agent and a rare error, 5 agents found it and 32 ended on it.

Both entries are descriptive, with one or two runs per condition and no hypothesis test. The main phase will run with predictions fixed in advance.

The world

The world, prompt, outcomes and scripted references were fixed before any model call (QX-2 phase 1 amendment). Every later experiment on this page uses it unchanged.

  • Strings and rules. Inputs are four letters from A–H, so there are 4,096 of them. A rule maps an input to an output.
  • The false rule HF is shift_symbols(1), which moves every letter one step forward. Every cell holds it at the start.
  • The true rule HT is HF followed by one substitution, so the two disagree on a share δ of the inputs.
    • δ = 1/8 (control): shift_symbols(1);subst(0,E,F). On input DAAA, HF gives EBBB and HT gives FBBB.
    • δ = 1/64 (main): shift_symbols(1);subst_if(0,E,F,1,H). It only differs when the input starts with DG.
  • Private evidence. Each cell has two examples. All of them lie on inputs where HF and HT agree, so no cell can see the error from its examples alone.
  • The catalog. It has 117 rules: the 101 base rules of the Life world, plus 16 substitution variants in four clusters. One counterexample still leaves at least two rules that fit, so finding HT takes more than one test.
  • Experiments. A cell has a budget of B tests, at most one per generation. It names an input and gets the true output one generation later. Only that cell sees the result.
  • Messages. 100 cells sit on a 10 × 10 torus and each hears its 8 neighbours. A message carries a number 0–7 and either the key of the rule the cell holds or one result from its memory, its own or relayed. A cell can only share a result it actually has, and the engine fills in the output, so every shared result is true.
  • A run lasts 12 generations. The outcomes are measured at generation 12:
    • abandonment is the share of cells no longer holding HF;
    • recovery is the share holding HT.

"On δ-inputs" is the share of tests that could refute HF; a random tester gets δ, that is 12.5 % or 1.6 %. A population run publishes about 1,200 messages in all, and about 930 of them name a rule.

Reading

  1. The setup works. Every delivered result was a true output of HT, the engine checks held throughout, and no answer failed the format.
  2. Experiments are cheap but not used. With four tests per cell, the population spent 44–70 of 400. The tests cluster on a few patterns: about half start with A, and AAAA and ABCD are frequent.
  3. When the error is rare (δ = 1/64), it is not found. None of 44 tests hit an input starting with DG. A random tester with the same 44 tests would have hit one about half the time.
  4. When the error is common (δ = 1/8), it is found but not passed on. Tests hit refuting inputs two to four times more often than chance. Cells that found a counterexample almost always left HF: 79 of 84 did, and 54 reached HT. But they kept naming rules in their messages instead of sharing the evidence: 6 messages in four runs carried a refuting result, each from a different cell. Only 14 cells reached HT without a counterexample of their own.
  5. Evidence that is shared does work. The 6 shared counterexamples reached 30 neighbours that still held HF. Within two generations, 15 of them left HF and 11 reached HT. Among cells that saw no counterexample, own or shared, 2.2 % left HF within two generations, and 1.2 % reached HT. The numbers are small, and this comparison was made after seeing the data.
  6. The signal field drifts to 0. The generation-0 messages the cells first see carry signals drawn uniformly from 0–7. Yet already in generation 1, 57–68 % of messages carry 0, and in generations 10–12, 89–95 %. No value marks HT or shared results.
  7. So the process breaks at different steps. An agent has to choose a test, read the result, update its own rule, decide to share the result, and neighbours have to act on it. At δ = 1/64 it breaks at the first step: no test found the difference. At δ = 1/8 the first three steps work, the last works when it gets the chance, and the fourth almost never happens.
  8. The single agent is an upper bound, not a matched control. It holds the whole budget and sees every result itself, so it does not isolate the cost of spreading the work. The scripted references in the table above do part of that, with the same distributed setup and fixed sharing policies. With four tests per cell, the populations did no better than with one.

Limits: one model, one world, one or two runs per condition, 12 generations. All numbers are descriptive.

2 · Luna, four cells

2026-11-15descriptive

The pilot left the rare-error cell at the floor. This entry runs the same world on Luna, the strongest model in the project, to see whether the floor belongs to the model or to the setting. It has one run in each of four cells: δ 1/64 and 1/8, with B 1 and 4. The design was fixed before the run (Luna amendment).

Recovery is the share of cells on HT at generation 12; the "20b" column gives the pilot's runs in the same cell. A random tester puts 1.6 % of its tests on δ-inputs at δ = 1/64 and 12.5 % at δ = 1/8. Finders are cells whose own test refuted HF. "Shared counterexamples" counts messages that carried a refuting result.

Reading

  1. Luna designs its experiments. Its first tests include DGHF, DCGF and DCHF, inputs that separate the substitution rules listed in the catalog. At δ = 1/64, 38 % of its tests landed on the rare inputs where the two rules differ. A random tester lands 1.6 %, and gpt-oss-20b landed 0 of 44.
  2. Every Luna finder adopts the true rule. All 195 cells whose own test refuted HF ended on HT. For 20b, 54 of 84 did.
  3. Luna shares the evidence. Each run carried 11–52 counterexamples to neighbours, from 9–44 different cells. Cells also pass on counterexamples they received: about half of the shared counterexamples are relays. In the rare-error cell with one test per agent, 5 agents found the error, 10 of the 11 shared counterexamples were relays, and 32 cells ended on the true rule, so 27 got it from others.
  4. Luna beats the scripted sharers. At δ = 1/64 with B = 4, it recovers 1.00. Scripted random testers that share refutations reach 0.61. The difference is the choice of tests.
  5. The signal field again carries no evidence. Luna's default is 7, where 20b's was 0. True-rule messages and shared counterexamples both carry 7, so no value marks evidence apart from rule names.

Limits: one run per cell, and the two δ arms at the same budget share their first generations. The catalog lists the true rule and its siblings, so this is testing within a given set of hypotheses, which is easier than finding an unlisted rule.
