Collective Falsification

Every agent in a population starts with the same wrong rule. Each can run a few experiments and tell its neighbours what it found. Does the population find its error?

By Artem Zvyagintsev, who designed, ran and analysed the experiments · github.com/corba777

The question that started this track was raised by Michal Valko (Isara Labs and Inria), who also proposed the comparison in entry 4.

Why this question

In a group where everyone holds the same belief, the evidence against it often reaches only one member. Human groups are known to handle this badly. In the hidden-profile studies (Stasser and Titus, 1985), groups spend their discussion on what everyone already knows and seldom bring out what only one member knows, even when that decides the answer.

Populations of language-model agents face the same problem whenever the agents see different data. This page measures it step by step: does an agent find the counterexample, change its own mind, pass the evidence on, and do its neighbours act on it?

Current answer, from two models: it depends on the model, and the failure has two separate causes.

  • gpt-oss-20b mostly stays wrong. When the error is rare (δ = 1/64), its tests never hit it. When it is common (δ = 1/8), agents find counterexamples and switch their own rule, but almost never pass the evidence on: 84 finders, 6 shared counterexamples, 10–26 % of the population on the true rule at the end.
  • Luna corrects the error. It picks tests that separate the candidate rules and shares what it finds. With a common error, 94–97 % of the cells are on the true rule by generation 6, in both runs. With a rare error it is slower and varies between runs: at generation 12 it had reached 32–100 % of the cells, depending on run and budget. Every rare-error run that was extended to 24 generations ended with all 100 cells on the true rule.

A counterexample moves a neighbour from one sender; a rule name does so only from a majority (Luna, one run per condition, entries 4 and 5). With a rare error and messages that carry only a rule name, 1 of 100 cells held the true rule after 24 generations; with a test result in the message, 99 or 100 did. With a common error, names alone carried all 100 cells, but a cell without evidence left the starting rule only once five or more of its eight neighbours named another one.

For gpt-oss-20b the limit is the sender (one run per condition, entry 6). Rule names alone moved almost no one: 32 cells held the true rule after 24 generations, 30 of them with a counterexample of their own. Allowed to share results, cells did so in 2 % of the messages where they could, and that was enough to reach 62. When the engine attached the counterexample for them, 83 did.

All of this is descriptive, with one or two runs per condition and no hypothesis test. The agents choose among 117 listed rules, and the true rule is one of them, so this tests whether a population can find and spread the evidence that picks out a rule it already knows about, not whether it can invent one. The main phase will run with predictions fixed in advance.

The world

The world, prompt, outcomes and scripted references were fixed before any model call (QX-2 phase 1 amendment). Every later experiment on this page uses it unchanged.

  • Strings and rules. Inputs are four letters from A–H, so there are 4,096 of them. A rule maps an input to an output.
  • The false rule HF is shift_symbols(1), which moves every letter one step forward. Every cell holds it at the start.
  • The true rule HT is HF followed by one substitution, so the two disagree on a share δ of the inputs.
    • δ = 1/8 (control): shift_symbols(1);subst(0,E,F). On input DAAA, HF gives EBBB and HT gives FBBB.
    • δ = 1/64 (main): shift_symbols(1);subst_if(0,E,F,1,H). It only differs when the input starts with DG.
  • Private evidence. Each cell has two examples. All of them lie on inputs where HF and HT agree, so no cell can see the error from its examples alone.
  • The catalog. It has 117 rules: the 101 base rules of the Life world, plus 16 substitution variants in four clusters. One counterexample still leaves at least two rules that fit, so finding HT takes more than one test. Because the true rule is listed, an agent never has to invent it, only to tell it apart from its neighbours in the catalog.
  • Experiments. A cell has a budget of B tests, at most one per generation. It names an input and gets the true output one generation later. Only that cell sees the result.
  • Messages. 100 cells sit on a 10 × 10 torus and each hears its 8 neighbours. A message carries a number 0–7 and either the key of the rule the cell holds or one result from its memory, its own or relayed. A cell can only share a result it actually has, and the engine fills in the output, so every shared result is true.
  • A run lasts 12 generations. The outcomes are measured at generation 12:
    • abandonment is the share of cells no longer holding HF;
    • recovery is the share holding HT.

Reading

  1. The setup works. Every delivered result was a true output of HT, the engine checks held throughout, and no answer failed the format.
  2. Experiments are cheap but not used. With four tests per cell, the population spent 44–70 of 400. The tests cluster on a few patterns: about half start with A, and AAAA and ABCD are frequent.
  3. When the error is rare (δ = 1/64), it is not found. None of 44 tests hit an input starting with DG. A random tester with the same 44 tests would have hit one about half the time.
  4. When the error is common (δ = 1/8), it is found but not passed on. Tests hit refuting inputs two to four times more often than chance. Cells that found a counterexample almost always left HF: 79 of 84 did, and 54 reached HT. But they kept naming rules in their messages instead of sharing the evidence: 6 messages in four runs carried a refuting result, each from a different cell. Only 14 cells reached HT without a counterexample of their own.
  5. Evidence that is shared does work. The 6 shared counterexamples reached 30 neighbours that still held HF. Within two generations, 15 of them left HF and 11 reached HT. Among cells that saw no counterexample, own or shared, 2.2 % left HF within two generations, and 1.2 % reached HT. The numbers are small, and this comparison was made after seeing the data.
  6. The signal field drifts to 0. The generation-0 messages the cells first see carry signals drawn uniformly from 0–7. Yet already in generation 1, 57–68 % of messages carry 0, and in generations 10–12, 89–95 %. No value marks HT or shared results.
  7. So the process breaks at different steps. An agent has to choose a test, read the result, update its own rule, decide to share the result, and neighbours have to act on it. At δ = 1/64 it breaks at the first step: no test found the difference. At δ = 1/8 the first three steps work, the last works when it gets the chance, and the fourth almost never happens.
  8. The single agent is an upper bound, not a matched control. It holds the whole budget and sees every result itself, so it does not isolate the cost of spreading the work. The scripted references in the table above do part of that, with the same distributed setup and fixed sharing policies. With four tests per cell, the populations did no better than with one.

Limits: one model, one world, one or two runs per condition, 12 generations. All numbers are descriptive.

Reading

  1. Luna designs its experiments. Its first tests include DGHF, DCGF and DCHF, inputs that separate the substitution rules listed in the catalog. At δ = 1/64, 38 % of its tests landed on the rare inputs where the two rules differ. A random tester lands 1.6 %, and gpt-oss-20b landed 0 of 44.
  2. Every Luna finder adopts the true rule. All 195 cells whose own test refuted HF ended on HT. For 20b, 54 of 84 did.
  3. Luna shares the evidence. Each run carried 11–52 counterexamples to neighbours, from 9–44 different cells. Cells also pass on counterexamples they received: about half of the shared counterexamples are relays. In the rare-error cell with one test per agent, 5 agents found the error, 10 of the 11 shared counterexamples were relays, and 32 cells ended on the true rule, so 27 got it from others.
  4. Cells that did not find the error themselves were moved by evidence, not by rule names. Of the 136 Luna cells that ended on HT without a counterexample of their own, 133 had first seen one shared by a neighbour. The same holds for gpt-oss-20b, where 12 of 14 had. This comparison was made after seeing the data.
  5. Luna beats the scripted sharers. At δ = 1/64 with B = 4, it recovers 1.00. Scripted random testers that share refutations reach 0.61. The difference is the choice of tests.
  6. The signal field again carries no evidence. Luna's default is 7, where 20b's was 0. True-rule messages and shared counterexamples both carry 7, so no value marks evidence apart from rule names.

Limits: one run per cell, and the two δ arms at the same budget share their first generations. The catalog lists the true rule and its siblings, so this is testing within a given set of hypotheses, which is easier than finding an unlisted rule.

3 · Luna, second runs and extended runs

2026-11-15descriptive

Two follow-ups to entry 2, each fixed before its data. The first runs every cell a second time, with independent arms (second-run amendment). The second extends runs that were still moving at generation 12 to generation 24 (extension amendment).

  • Second runs. They use the same model, prompt and settings as entry 2, with a fresh cache keyed by arm, so no answer is reused. They cost $2.51.
  • Extended runs. A run is restored to generation 12 from its stored answers, and the restored rules, tests and messages equal the stored trace. It is then played on to generation 24. The prompt states the run length, so generations 1–12 were played under "12 generations" and the prompts from generation 13 on say "24". Each call sees only its own prompt.
    • Luna run 1 at δ 1/64, B 1 was chosen after its data were seen.
    • The second runs were extended by a rule fixed in advance: extend if 1–99 cells hold HT at generation 12, and more than at generation 9. The rule selected both δ 1/64 cells and neither δ 1/8 cell.
    • The extensions cost $1.85.

Reading

  1. Given time, every rare-error Luna run reaches the whole population. The three extended runs reach 100 cells on HT by generation 16, 18 and 22. With one test per cell, the run that stood at 32 % at generation 12 was not stuck, only slow.
  2. The common-error cells replicate. In both runs, both budgets reach the ceiling within the first 6–10 generations.
  3. The rare-error cells vary between runs, in both directions. At B = 4, run 2 stood at 79 at generation 12 against 100 for run 1, and it shared half as many counterexamples (24 against 49) with similar test quality. At B = 1, run 2 stood at 55 against 32, with 9 finders against 5. With few finders, how many of them share decides the pace.
  4. Shared evidence still drives the converts. In the second runs, 131 of the 132 cells that reached HT by generation 12 without a counterexample of their own had first seen one shared by a neighbour. Over the whole of extended run 1 the share is lower: 70 of its 85 such cells. Late converts also follow rule names. This line was first found after seeing the data, and the second runs replicate it.
  5. The test budgets get used. By generation 24, 98–100 of the 100 cells at B = 1 have spent their test. Tests after generation 12 added 10–23 finders per run.

Limits: two runs per cell. The extended runs carry the splice at generation 12. The gpt-oss-20b runs from entry 1 are queued for the same extension.

4 · Rule alone against rule plus counterexample (Luna)

2026-11-16descriptive pilot

Entries 1–3 found that cells which reach the true rule without a counterexample of their own had almost always seen one shared by a neighbour. That was noticed after the data were seen, and it does not show that the evidence causes the switch. Michal Valko proposed the test: compare sharing the rule alone with sharing the rule plus a counterexample, under matched budgets. This entry runs it for Luna (amendment, fixed before the runs).

Configuration

Three message conditions. Everything else is the same: the world, δ = 1/64, one test per cell, one message per generation and 24 generations, stated in the prompt from the start.

conditionwhat a message carries
rule onlythe key of the rule the cell holds
rule + chosen resultthat key, and one test result from memory if the model adds it
rule + attached resultthat key, and the engine attaches the latest result against HF
  • The engine attaches a result only when the cell has one that contradicts HF: the most recent one in its memory, its own or received.
  • In the third condition the sender's prompt is the "rule only" prompt, word for word. The sender is not told that a result will be attached, and a receiver cannot tell an attached result from a chosen one.
  • The attach rule reads only HF, the rule every cell starts with. It never uses the true rule.
  • One run per condition, 2,400 calls each, with separate caches. The three runs cost $3.94.

Reading

  1. A rule name from one neighbour does not move a cell. In the "rule only" run, three cells found the error, left HF and named another rule to their neighbours for 9, 16 and 23 generations. A cell on HF heard a neighbour name another rule in 332 cases, almost always from one neighbour of its eight, and left HF in one of them, for one generation. Entry 5 shows that names from a majority of neighbours do move it.
  2. A counterexample from one neighbour does. Of the cells that first received a counterexample while on HF, 74 of 91 left HF within two generations when sharing was the model's choice, and 90 of 96 when the engine attached it. Across the three runs, a cell with no counterexample in its memory left HF in 1 of 3,013 cases.
  3. The gap is not a difference in discovery. The "rule only" run had 3 finders and the "attached" run had 4.
  4. Luna shares enough on its own. When a publishing cell held a counterexample, it added one to 46 % of its messages. That run is slower at first than the attached run (10 against 46 cells at generation 6) and level with it by generation 12.

Limits: one run per condition and one model, with no hypothesis test. In the "rule only" run the finders mostly named a neighbouring rule that fits their single counterexample as well as the true rule does; the true rule itself was named in 106 of the 332 cases. In 299 of them only one of the eight neighbours named another rule, so this run shows that one name of eight does not move Luna; it does not show what several names would do; entry 5 tests that. The same three conditions are now running on gpt-oss-20b at δ = 1/8, where cells find counterexamples but rarely share them.

5 · Rule only, when many neighbours name the rule (Luna)

2026-11-16descriptive

In entry 4 a cell almost never heard another rule from more than one neighbour, so that run tested one dose. This entry repeats the "rule only" condition where the error is common (δ = 1/8) and many cells find it, so that cells without evidence of their own hear another rule from several neighbours (amendment, with the measures, reference levels and readings fixed before the run).

Configuration

  • The same model, prompt and settings as the "rule only" run of entry 4, with δ = 1/8, one test per cell, 24 generations, one run. It cost $1.06.
  • A cell is "without evidence" while it has no test result that contradicts HF. No results travel in messages, so only its own test can give it one.
  • For each such cell on HF, we count the neighbours that named another rule in the previous generation, and whether the cell then left HF.

"Naming neighbours" are those of the cell's eight neighbours that named a rule other than HF in the previous generation. A case is one cell in one generation, on HF and without evidence. Reading

  1. Rule names do move Luna, at a high dose. The amendment's test of this was the rate at three or more naming neighbours: 37 of 99 cases, with a lower bound of 0.27 against a reference of 0.021 from entry 4. The 33 cells that never had a counterexample all ended on the true rule.
  2. The response is a step at the majority. With up to four of eight neighbours naming another rule, no cell left HF in 141 cases. With five or more, 37 of 41 did. This split was found after seeing the data.
  3. This is what separates a name from a counterexample. In entry 4 a counterexample from a single neighbour moved 74 of 91 cells within two generations. A name needs five. Where the error is rare, few cells find it, a majority of naming neighbours never forms, and only shared evidence can carry the population.
  4. The comparison fixed in advance is close to its boundary. Of the cells first exposed to three or more naming neighbours, 20 of 38 left HF within two generations (interval 0.34–0.71). That interval touches the evidence level from entry 4 (0.70–0.90), so by the rule written before the run a name at this dose counts as "about as strong as a counterexample". The step in point 2 shows why the figure is mixed: three naming neighbours do nothing, five do almost everything.

Limits: one run and one model. A cell appears in several cases, so the case counts are not independent. Intervals are exact 97.5 % intervals, two comparisons with a Bonferroni correction. The majority step matches how this model responded to rule names in the earlier Constitutional Life experiments, where no test is available at all.

6 · Rule alone against rule plus counterexample (gpt-oss-20b)

2026-11-17descriptive pilot

The three message conditions of entry 4, on the smaller model. In entry 1 gpt-oss-20b found counterexamples at δ = 1/8 but shared them in a handful of messages. The third condition, where the engine attaches the counterexample, shows whether that is what holds the population back (same amendment as entry 4).

Configuration

  • gpt-oss-20b, δ = 1/8, one test per cell, 24 generations, one run per condition, 2,400 decisions each.
  • The conditions, prompts and attach rule are those of entry 4.
  • One deviation: the third run stopped at generation 19 when a prompt outgrew the server's context window. It was resumed with a larger window and the same request; generations 1–18 were replayed from the stored answers, with identical prompts.

Reading

  1. Rule names barely move this model, at any dose. In the "rule only" run about a third of the cells found the error and named another rule, so many cells heard it from several neighbours. Of the 66 cells that never had a counterexample, 2 ended on the true rule. With three or more naming neighbours a cell left HF in 11 of 259 cases, and there is no step at the majority as there is for Luna.
  2. Evidence moves the receivers about as it does for Luna. Of the cells that first received a counterexample while on HF, 35 of 47 left it within two generations when sharing was the model's choice, and 64 of 83 when the engine attached it. For Luna the figures were 74 of 91 and 90 of 96.
  3. The sender is the limit. The three runs had about the same number of finders (34, 32, 29). When a publishing cell held a counterexample, it added one to 19 of 921 messages (2 %; Luna: 46 %). Those 19 messages were enough to double the number of cells on the true rule. Attaching the counterexample for the sender raised it again, from 62 to 83.
  4. What remains is on the receiver's side. With attached evidence 91 cells left HF, but at generation 12 thirty of them held some other wrong rule, and 8 still did at generation 24. This model accepts that the starting rule is wrong sooner than it finds the right replacement.

Limits: one run per condition, with no hypothesis test. In the "chosen result" run 10 cells went back from the true rule to HF in the last generation (72 cells at generation 23, 62 at generation 24); we have not explained this.
